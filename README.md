# Mgmail

多账户 Gmail 原生 macOS 客户端。UI 参考 Apple Mail 三栏布局，**通过 OAuth 2.0 + Gmail API** 操作邮件（不走 IMAP）。

- 技术栈：Swift 6 + SwiftUI + AppKit/WebKit，纯系统框架，零第三方依赖。
- 构建：Swift Package Manager（无需完整 Xcode）。

## 构建与运行

```bash
Scripts/build_app.sh          # release 编译并打包成 dist/Mgmail.app
Scripts/build_app.sh run      # 打包后启动
Scripts/build_app.sh debug run # debug 编译并启动
```

也可直接 `swift build` / `swift run`；日后装了 Xcode 可 `open Package.swift`。

## 首次配置 Gmail 访问（必需）

应用通过你自己的 Google OAuth 客户端访问 Gmail：

1. https://console.cloud.google.com/ → 新建项目。
2. 「API 和服务」→ 启用 **Gmail API**。
3. 「OAuth 同意屏幕」：User Type 选 **External**；scope 添加 `https://www.googleapis.com/auth/gmail.modify`；把你的 Gmail 地址加入 **Test users**。
4. 「凭据」→ 创建 OAuth 客户端 ID → 应用类型 **桌面应用** → 下载 JSON。
5. 把 JSON 重命名为 `oauth_client.json`，放到：
   `~/Library/Application Support/Mgmail/oauth_client.json`
6. 启动应用 → 「我已放好文件，重新检测」→「添加账户」→ 在浏览器完成授权。

> 注意：同意屏幕处于「测试」状态时，Google 的 refresh token 约 7 天过期，届时需重新登录。

## 功能（v1）

- 多账户 OAuth 登录（PKCE + 回环重定向，refresh token 存 Keychain）
- 读取收件邮件：会话列表、正文（WKWebView，默认拦截远程内容）、附件下载；信头按需显示收件人 / 抄送 / 密送（有才显示，右栏点一下摊开长名单）
- 标签管理：加/去标签、已读未读、加星标、归档、新建/改名/删除标签
- 写邮件：撰写（⌘N）、回复 / 全部回复 / 转发（⌘R、⇧⌘R、⇧⌘F）、抄送密送、附件、存草稿
- 本地搜索（⌘F）：在已同步的邮件里按发件人 / 主题 / 摘要搜，支持 `from:` `is:unread` 这类限定词
- 查看原始邮件：右键任意一封 → 拆好的头字段 + 一字不改的报文原文，可拷贝、存成 `.eml`
- 新邮件通知：系统横幅 + Dock 未读角标，可按账号和邮件类别筛

## 写邮件

每封信一个独立窗口，可以同时开几封。发件人默认取当前在看的那个账号，多账户时能改。
回复带引用原文，并接进原会话（`In-Reply-To` / `References` 加 Gmail 的 `threadId`）；
转发不接——那本来就是另起一串。

- **正文是纯文本编辑**，但发出去的是 `text/plain` + `text/html` 两份：纯文本保底，
  HTML 让换行和引用块在主流客户端里显示得体。富文本编辑留待以后。
- **附件上限 3.5MB**（原始字节）。Gmail 的 JSON 简单上传限整封报文 5MB，base64 会
  撑大三分之一，所以留出余量；超了在附件栏直接标出来。大附件要走 resumable upload。
- **权限**：`gmail.modify` 已含发送权限，不必额外申请 scope。

## 自检

四套自检，都是纯 Foundation、独立编译即可运行：

```bash
Scripts/check_mime.sh       # 报文拼装
Scripts/check_mailbox.sh    # 邮箱归属判断
Scripts/check_search.sh     # 本地搜索的解析与匹配
Scripts/check_rawsource.sh  # 邮件原文的拆解
```

盯的都是那些**本地看着没错、事后才发现不对**的地方。

`check_mime.sh`（`Compose/MimeBuilder.swift`）——中文主题的 RFC 2047 编码、
长主题切成多个 encoded-word 且不切断汉字、`"Doe, John" <j@d.com>` 里的逗号不被拆成
两个收件人、`text/html` 必须排在 `text/plain` 之后、`References` 链不重复追加、
中文附件名的 RFC 2231、行尾一律 CRLF 没有裸 LF。拼错了不会当场报错，
是对方收到乱码时才发现。

`check_mailbox.sh`（`Gmail/Mailbox.swift`）——各个邮箱收哪些信。要害在于删除和
标记垃圾在 Gmail 里只是加个标签，`SENT`、`STARRED`、用户标签一个都不会掉：
不把它们排除掉，删过的已发送邮件就会一直赖在「已发送」里，和 Gmail 网页版对不上。

`check_search.sh`（`Gmail/MailSearch.swift`）——搜索词怎么解析、怎么匹配。盯的是那些
「搜不到但不报错」的地方：`from:` 才打了一半就把列表清空、中文输入法的全角冒号不认、
带冒号的网址被当成限定词、显示名挡住了发件人地址、全角字母搜不到半角原文。
搜索出了错没有任何提示，只会让人以为邮件丢了。

`check_rawsource.sh`（`Gmail/RawSource.swift`）——报文原文怎么拆。盯的是「屏幕上看着
像那么回事、其实读错了」的地方：CRLF 在 Swift 里是**一个**字符，按 `"\n"` 切的话整个
头部会连成一条；折行不展开就少半条 `Received`；encoded-word 不解开中文主题就是一串
base64，相邻两个词之间的空白不吞掉则每隔几个字多个空格；非 UTF-8 的报文解不开不能
整封空白。看原文的场合（查退信、查发件人是不是伪造的）恰恰最经不起看错。

> 它们不是 `swift test`。本项目按设计不依赖完整 Xcode，因而没有 XCTest 也没有
> swift-testing 可用；这几个脚本用 `swiftc` 把检查文件连同被检查的几个源文件编出来跑，
> 是真跑断言，只是没有测试框架的报告格式。日后装了 Xcode 可以改回 XCTest。

## 数据与刷新

邮件数据按**账户**组织成一个本地池（`MailStore`），侧栏里各个邮箱、标签、分类都只是
对这个池子的本地过滤——切换邮箱不发任何网络请求。

这么组织是因为取数的源头本来就是账户级的：`users.history.list` 返回整个账户的变化，
`users.labels.list` 返回整个账户的标签，而「在哪个邮箱、读没读、有没有星标」在 Gmail
里全都是每封邮件 `labelIds` 上的值，不是独立的属性。

读取邮件时的联网只发生在四个时刻：**冷启动**、**定时（60 秒）**、**睡眠唤醒之后**、
**手动点刷新**（侧栏账号行上的按钮）。每次都是同样两步——先 `labels.list` 拉标签定义，
再 `history.list` 同步邮件变化。history 已经带回了变动的标签，本地按增删应用即可，
不必逐封回头去问。

定时那一档覆盖**全部账号**，不只当前分组——分组是看的方式，不是收信的范围，
分组外的账号来了信同样要能发现（否则新邮件通知就有洞）。定时器因此挂在应用上而不是
列表视图上：macOS 关掉最后一个窗口进程仍在，定时器不该跟着窗口一起没。

此外**发信或存草稿之后**也会立刻催一次该账号的同步：那封信是 Gmail 服务端生成的，
不主动问一次，本地池子要等到下一次定时刷新才知道「已发送」里多了东西。

- **回溯范围**：每个账户从新往旧拉，到「最多邮件数」或「最多时间」为止（设置 → 同步）。
  范围之外的邮件不在本地，所以已发送、冷门标签这类邮箱可能是空的——这是预期行为。
- **垃圾邮件 / 废纸篓**：Gmail 的列表接口默认不返回，只在第一次点进去时单独拉。
- **正文**：不可变，所以一封邮件（或一串会话）只拉一次，之后永远走磁盘缓存。
- **本地操作**：先改池子让界面立刻响应，再发请求，失败了才回头拿服务器状态纠正。
- **收件箱对账**：每 6 小时拿服务器的收件箱跟本地核一遍，对不上的重取信头。
  上面每条线都不回头（回溯翻过的页不重来，增量只认位点之后的变化），漏掉一封
  本来就是永久的；对账是唯一那条认账的路，代价是一次只回 id 的 list。

另外，取信头时个别失败的、以及增量报告了变动但池子里还没有的邮件，都会记进账户的
「欠账」清单，每轮同步补取一批——这两种邮件同样没有别的机会再被拉到。

## 搜索

搜索是**纯本地**的：邮件都在账户池里，搜索不过是对同一份数据的又一层过滤，
和切换邮箱一样，一个网络请求都不发。搜索框在窗口右上角（⌘F 直接把光标送进去，
ESC 清掉）。

搜的范围是**已经同步到本地的那些邮件**，字段只有**发件人（名字和地址）、主题、摘要**。

> 正文刻意不参与。正文是「打开过或预取过才在磁盘上」的（见「数据与刷新」），
> 拿它当搜索范围，结果会随「碰巧读过哪几封」变化——一个时灵时不灵的搜索比没有更坏。

- **范围**：搜索时工具栏上多一个范围下拉——**当前邮箱**（默认）、**各个账号**
  （当前分组里的，按名字列出）、**所有账号**。选账号那档不再受选中的邮箱限制，
  搜的是那个账号的全部邮件，垃圾邮件与废纸篓除外，和「所有邮件」邮箱一个规矩。
  中间那档指名道姓而不是含糊的「当前账号」：搜起来之后列表里什么账号的信都有，
  「当前」是谁就没人说得清了，而那正是选范围时最该确定的事。做成下拉也是同理——
  账号一多，摊开的范围条就把中栏顶出去了。
  「所有账号」不看分组：分组是看的方式，而要找一封不知道在哪的信时，它不该是墙。
  跨账号的结果每行标出来源账号，否则看到的人会以为都是当前账号的。
  搜不到时空白页会提示怎么放宽、写清能用哪些限定词，以及本地回溯到了哪一天。
- **限定词**：`from:` `subject:` `is:unread` `is:read` `is:starred` `has:attachment`，
  多个条件之间是「且」，可以和裸词混用。带空格的短语加引号（`subject:"周会 纪要"`）。
  中文输入法下的全角冒号和全角引号同样认，`发件人：` `主题：` 也认。
- **认不出的限定词按字面量搜**：`https://a.cn` 里的冒号不会被当成限定词——
  否则搜个网址会一封都搜不到，而且看不出为什么。
- 大小写、变音符号、全半角都不计较：搜 `jose` 找得到 `José`，搜 `Ｑ３` 找得到 `Q3`。
- 会话模式下按整串算：串里有一封命中，整串就是一条结果。
- 换邮箱会清掉搜索词——搜索是一次性的动作，留着它只会让新邮箱看起来是空的。

## 新邮件通知

新邮件从哪来是确定的：`history.list` 里的 `messagesAdded`。回溯拉取走的是另一条线，
所以首次同步几百封邮件不会变成几百条通知——这不是额外加的判断，是两条路径本来就分开。

**没有走 Gmail 的推送（`users.watch` + Pub/Sub）**，还是 60 秒轮询。推送要求一个公网
HTTPS 端点或 Pub/Sub pull 订阅，桌面应用两样都没有，用户得自己在 GCP 里建 topic、建
订阅、授权推送服务账号，还要每 7 天续订一次 `watch`——配置门槛会从现在的六步涨到十几步。
而空的 `history.list` 只有几百字节、2 个配额单位，每天 1440 次连限额的零头都算不上。
这笔账不划算。

哪些邮件会弹：**躺在收件箱里的未读来信**。自己发出的信、刚存的草稿、被判为垃圾的、
已进废纸篓的都不算——它们在 `messagesAdded` 里同样是「新增的邮件」，得靠标签筛掉，
而标签要等信头取回来才有，所以判断做在取完 metadata 之后。

- **攒一小会儿再报**：最后一封新邮件到达后再等 0.6 秒，期间来的并成一批。三封以内逐条
  报，超过就报个总数（「27 封新邮件」）——关了一夜再打开正是这个场面，逐条弹是灾难。
- **只通知主要邮件**（默认开）：推广、社交、论坛不弹。「更新」不在其列——订单确认、
  验证码、服务告警都落在那一类。
- **Dock 角标**：所有账号收件箱的未读总数，不随分组变化。它不依赖通知权限，
  所以拒绝了通知授权时这一半仍然能用。
- **点通知**跳到那封邮件；账号在当前分组之外时先回到「全部」，否则跳过去也看不见。
  主窗口已经关掉的话会重新开一个。
- **按账号**可以单独关（设置 → 通知）。关掉的账号既不弹通知，也不计入角标。

> **通知要求 app 已签名**。`Scripts/build_app.sh` 找不到签名证书时会警告——未签名的
> bundle 拿不到稳定的通知身份。直接 `swift run` 跑的裸可执行文件更是没有 bundle，
> 通知在那种跑法下整个关闭（不会崩，设置页会说明原因）。

## 查看原始邮件

右键任意一封邮件（中栏列表、右栏卡片头、独立窗口的信头）→「查看原始邮件」，
开一扇窗看这封信投递进来时的那份 RFC 5322 报文。取的是 Gmail 的 `format=raw`，
**没有经过 Gmail 加工**：头字段一条不少、顺序不动、非 ASCII 还是编码态。

分两页看，因为两种用法本来就不同：

- **邮件头**：拆好的头字段表。折行展开成一条，encoded-word（`=?UTF-8?B?…?=`）解成中文，
  编码过的那几条把原样也摆在下面一行——解码是我们代劳的，出了岔子得能看见没解之前
  长什么样。同名头字段（一封信经过几跳就有几条 `Received`）一条都不合并、不去重，
  否则「这封信打哪儿来」就永远查不出来。
- **完整原文**：一字不改的整封报文，工具栏那个放大镜开系统查找栏（⌘F 被「搜索邮件」
  占着，到不了这扇窗）。

拷贝按当前这页给（在头那页给的就是那几条头），「存为 .eml」写的是**原始字节**而不是
屏幕上那份解码后的文本，存出来的文件别的邮件客户端能原样打开。

原文不进缓存：正文缓存那套是给天天要看的东西准备的，原文是偶尔查一次的，
每次现取反而省事，也保证看到的一定是服务器上现在那份。

## 网络活动日志

每一次网络往返都会记一条：**哪个账号**、**在做什么**（「检查新邮件」「获取邮件列表（收件箱）」
「下载附件」…）、方法与 URL、HTTP 状态码、耗时、响应字节数、重试次数、失败原因。

覆盖的是所有联网出口——Gmail 请求、批量请求、OAuth 令牌、头像下载，登记都在各自的
唯一出口里做，新加接口会自动出现在日志中。请求体一个字都不记（里面有 client secret
和 refresh token）。

- **底部活动栏**：有活动时窗口底部浮出一栏，说明此刻在替哪个账号做什么；闲下来自动收起。
  失败会在那儿停留几秒。
- **活动窗口**（窗口 → 活动，⌘0）：按账号、类别、关键词查，可只看失败；选中一行看完整请求。
- **磁盘日志**：`~/Library/Application Support/Mgmail/Logs/activity-YYYY-MM-DD.jsonl`，
  一行一条 JSON，保留 7 天。内存里只留最近 1000 条，更早的翻文件。

## 本地数据

都在 `~/Library/Application Support/Mgmail/` 下：

```
oauth_client.json          Google OAuth 客户端配置（自己放进去的）
tokens/<账号>.token        refresh token，权限 0600
avatars/<账号>.png         账号头像
Cache/<账号>/
  pool/     该账户的邮件池（列表数据的唯一来源）
  labels/   标签定义
  sync/     增量同步位点
  thread/   会话正文（不可变，拉一次就一直留着）
  message/  单封正文
  inline/   正文里的内联图片
Logs/                      网络活动日志，保留 7 天
```

账号目录名是「邮箱去掉符号 + 地址摘要」，缀摘要是为了让 `a.b@x.com` 和
`a_b@x.com` 不会落到同一个路径上。旧布局在启动时由 `Cache/StorageMigration.swift`
一次性搬过去，那是模块化的一次性代码，不在日常读写路径上。

`thread/`、`message/`、`inline/` 会按「最后一次打开」回收（超过 200MB 或 120 天没碰过）。
`pool/`、`labels/`、`sync/` 不参与回收——那是同步位点和列表本身，丢了要重新全量拉。

> `tokens/` 里是**长期有效**的 refresh token，明文存放，靠文件权限保护。
> 这是相对钥匙串的一次明确降级（换来的是不再反复弹授权框），细节见 `Auth/TokenStore.swift`
> 的注释。拿到这个文件就等于拿到你的 Gmail 读写权限，别让它离开这台机器。
